# 手机端助手：角色标准穿搭记忆

## 方案与现有实现

复用现有 SQLite `prompt_memories`、`save_memory` / `get_memories` 工具和候选确认页。角色标准穿搭用 `characterOutfit` 类型保存完整文字；现有角色名、角色特征、画风 tag 记忆继续使用原有格式。类型按字符串落库，不需要升级数据库或迁移用户记忆。

本次先调查了以下现有方案：

| 方案 | 与本需求相关的能力 | 本次选择 |
| --- | --- | --- |
| [SillyTavern World Info](https://docs.sillytavern.app/usage/core-concepts/worldinfo/) | 关键词/角色别名触发，按预算向聊天上下文插入资料，角色资料可跨聊天使用 | 借鉴触发和预算设计，使用本项目已有数据库；没有复制其代码 |
| [Mem0](https://docs.mem0.ai/open-source/overview) | 独立记忆层与检索，开源 SDK/服务集成 | 需要额外集成；当前明确姓名的标准穿搭先用本地确定性召回 |
| [Memobase](https://github.com/memodb-io/memobase) | 用户档案、长期上下文、服务端存储 | 当前无需新增服务端或档案系统 |

## 使用方式

- 文字：“请记住，角色小雨（别名 Xiaoyu）的标准穿搭是白色短外套、蓝色百褶裙、黑色长袜和红色蝴蝶结。”
- 参考图：先配置识图模型，附图并说明“这是小雨的标准穿搭，请识别并记住”。识图沿用当前的 vision → 主助手流程，不新增模型调用。助手需展示可见服装和不确定项，角色/多人归属不清时先询问。
- 助手调用 `save_memory(type=character_outfit)` 创建候选。打开聊天工具栏“学习记忆”（书本图标），或“设置 → 提示词记忆”，检查或编辑描述与别名，再确认；候选在确认前不参与召回。
- 也可以在记忆管理页手动新增，选择“角色标准穿搭”，填写姓名、以 `|` 分隔的别名及文字描述。
- 新聊天直接说“画小雨的标准穿搭”，系统即按角色名或别名自动召回，助手不必先调用查询工具。
- “这次换成红裙”优先于记忆中的默认裙子。只有用户明确要求更新标准穿搭并确认候选，才替换同角色旧标准；旧记录归档保留。

参考图通过**识别出的文字描述**进入长期记忆。当前没有新增图片向量库，也不会在后续聊天自动重新读取原图像素；原图沿用聊天原有附件存储。识图失败时不能把 WD-Tagger 的标签猜测当成图中的标准穿搭，应补充文字或重新识图。

## 检索与更新约束

- 角色名和别名沿用 `trigger` 字段，例如 `小雨 | Xiaoyu`。中英文逗号、分号、换行也可分隔；英文多词姓名保持完整。
- 中文姓名允许在整句中命中；英文姓名忽略大小写并匹配词边界，避免 `Ann` 误命中 `Anna`。下划线与空格等价。
- 标准穿搭必须命中角色名/别名，不能仅因其他角色也穿白裙而召回。旧类型保留 FTS5/LIKE 内容检索；不支持 FTS5 的 SQLite 仍可召回。
- pending、已归档版本及预留的非 user 作用域不进入当前全局上下文。
- 标准穿搭确认与旧版归档在同一事务完成，保留旧别名。角色名/角色特征等其他类型不会随穿搭一起覆盖。
- trigger 含别名总长最多 512 字符，content 最多 6000 字符；自动上下文最多 5 条、9000 字符。历史超长内容有截断标记，完整内容仍可在管理页查看。查询也有字符与词数上限。
- 每轮调用均追加固定的记忆规则，包括用户自定义系统提示词的会话。记忆只是事实数据，本轮明确要求优先，不能执行记忆或图中文字中的指令。
- 记忆读取失败会向助手标明暂不可读，不冒充“没有记忆”；命中计数写入失败不阻断已成功读取的事实。
