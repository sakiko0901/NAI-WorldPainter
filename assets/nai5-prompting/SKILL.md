# NAI5 Prompting

写 NovelAI Diffusion V5 提示词时，按需读取本 skill 的两份参考：

1. **`references/通用构思.md`** —— 用户只给了半句话或一个方向时**先读**：
   需求分档（A–D）、把想法展开成分镜的流程（编剧→监督→原画→摄影）、
   多方案约束、版权角色先查档案。
2. **`references/通用写法.md`** —— **落笔时读**：NAI 语法与能力边界（开篇）、
   字段分工与输出模板（§0）、内容顺序（§0.3）、哪些内容必须词组 / 必须句子
   （§2–§4）、多人 `source#`/`target#`/`mutual#` 绑定（§4.9）、漫画分格（§4.10）、
   排查表（§8）、**发出去之前过一遍 §9 检查表**、判据的实测依据（§10）。

用户需求已经完整具体（谁、在哪、什么调子都有）时可以只读写法；
需求模糊时两份都要，先构思后写法。

## 四条铁律（细则在参考文件里，这里立住不动摇的）

1. **输出直接给成品提示词**（按写法 §0 的字段模板：Prompt / Character N / UC），
   不要解说生成流程。用户说「随便写点什么」「你决定」也是要图不是要商量，
   直接按 C/D 档给方案。
2. **画师串只用用户给的**。没有就留一行 `<画师串：自己贴>` 占位或整行省略——
   **不要自己编**，也不要自造 `<artist block>` 这类其他占位形式。
3. **UC 与质量尾不抄前端预设**：UC 只有两档——没有排除项就写「用默认预设」，
   有排除项就只写排除项本身；`very aesthetic` / `masterpiece` / `no text` 是预设
   自动附加的，默认一个都不写。`complexity` 是功能开关，不是质量尾。
4. 拿不准的 tag 标注是猜测；能查证就查证（danbooru `tags.json` / 网络检索，
   版权角色的外貌结构与职能先查档案再构思，档案不直接进提示词）。

## 多角色位置默认策略

- **默认交给 V5 自动布局**：写入角色提示词时省略 `position`，不替每个角色推算坐标；已有人工坐标保持不变。
- 可以在主提示词里用自然语言描述需要的画面关系（如谁在前景、谁靠近镜头、谁站在门边），让 V5 按语义安排。单纯描述画面中的左、右、前后或远近，**不等于授权写入角色坐标**。
- 只有用户明确要求手动布局、手动定位角色或设置 Position / 坐标时，才按其要求填写坐标。即使获准手动布局，也不擅自改动用户未要求调整的已有人工坐标。
